## Summary
Bookmarks dragged from the address bar onto the bookmark bar now stay where they were dropped instead of jittering and jumping to the end.

## Changes
- **Fixed** (server): A newly created bookmark is inserted at the index the browser reports. Later siblings shift down and the new node gets a sort key between its neighbours. Previously the server stored the raw index with an end-of-collection sort key, leaving two siblings on the same position; the next renumbering (by sort key) moved the new link last and the extension mirrored that order. Applies to both `/bookmarks/sync` and `/bookmarks/delta` creates.
- **Fixed** (server): Siblings shifted by a create get a fresh `server_version`, so the extension accepts the new order instead of pushing its stale positions back up.
- **Added** (server tests): Regression tests for mid-group creates on `/sync` and `/delta`, including a follow-up reorder that must keep the dropped link in place.

## Upgrade notes
Update the server container; the fix is server-side. The extension version bump carries no behavior change, so reloading the extension alone does not fix this.
