## Summary
GitHub releases now carry real release notes instead of a fixed placeholder sentence.

## Changes
- **Changed** (release tooling): `deploy.sh` requires a committed `release-notes/vX.Y.Z.md` with `## Summary`, `## Changes`, and `## Upgrade notes` sections, and refuses to release before any side effect if it is missing. Previously every release was published with the hardcoded text "Production release of Lio with packaged browser extension bundles."
- **Added** (release tooling): `scripts/release-notes.sh` builds the release body from the curated notes file, every commit since the previous tag, and a GitHub compare link. It also works on existing tags for backfilling (`gh release edit`).
- **Changed** (docs): `AGENTS.md`/`CLAUDE.md` add a "Write Release Notes" step with the required format and content rules; `DEPLOYMENT.md` documents the gate, the composer, and how to fix notes on a published release.

## Upgrade notes
None. No extension, server, or web UI behavior changed. Releases before v0.9.71 still show the old placeholder text.
